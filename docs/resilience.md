# Надёжность и оптимизация в ЛР7

## gRPC

Каждый клиентский вызов имеет timeout. Для временных ошибок используется не более трёх попыток с экспоненциальной задержкой. Постоянные доменные ошибки не повторяются.

## Kafka

Producer повторяет публикацию ограниченное число раз. Consumer выполняет bounded retry handler-а. После исчерпания попыток poison message переносится в `profitability.events.dlq`, после чего исходный offset коммитится, чтобы одна некорректная запись не блокировала партицию.

## Redis cache

Кешируется master data context, используемый Costing Service. Это уменьшает количество повторных gRPC-вызовов при расчётах. Cache имеет TTL и инвалидируется после `MasterDataChanged`.

## Graceful degradation

Ошибка cache не останавливает бизнес-сценарий. Система продолжает выполнение через исходный gRPC источник данных.

## Logging

gRPC, Kafka, cache и ошибки пишутся в структурированном JSON-формате. Для Kafka сохраняется `correlationId`, позволяющий связать события одного распределенного сценария.
